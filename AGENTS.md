# General rules for the project

## Project Context (Reference)

`github.com/powerman/slogx` is a Go library with extensions for `log/slog`;
the public API overview is in `doc.go`.
Non-test code must stay stdlib-only ("zero required external dependencies"):
other modules in `go.mod` are used only by tests.

### Structure

- `*.go` in the root: package `slogx`, one feature per file with its own `_test.go`.
  - Tests are in the external package `slogx_test`;
    `export_test.go` exports internals they need.
  - `mock.handler_test.go` is generated by `go generate` (see `generate.go`).
- Files marked `vendored` in `.gitattributes` are copied verbatim from Go sources.
  Do not modify them:
  `mise run fix` restores them and refuses to run if they have uncommitted changes.
- `internal/` is a fork of `log/slog` sources (version in `internal/README.md`),
  so `LayoutHandler` stays 100% compatible with `slog.TextHandler` at comparable performance.
  See `internal/README.md` for the upstream Go version and what was changed.
  Keep it close to upstream to ease syncing.
- `internal/layout_handler.go` is the stdlib `commonHandler` (from `handler.go`)
  renamed, stripped of JSON support and extended with layout support.
  The public `LayoutHandler` (`layout_handler.go`) only converts options
  and delegates to `internal.LayoutHandler`.
  `internal/text_handler.go` exists only to run the stdlib test suite against `LayoutHandler`;
  tests for new LayoutHandler features live in the root package.
- `testdata/lint/`: separate module to manually check the linter config recommended in `README.md`.

### Commands

Use these commands for corresponding tasks:

- `mise run` — default task, runs: fmt, lint and test.
- `mise run fix` — `go fix` plus `golangci-lint run --fix`.
- `mise run generate` — regenerates mocks.
- `mise run fmt` — fixes formatting. CI fails if `generate` or `fmt` changes any file.
- `mise run lint` — runs all linters.
- `mise run test` — runs the suite twice, with and without `-race`,
  because some forked tests in `internal/` skip themselves under `-race`.
- `go test -run TestName ./...` — run single test.

CI also runs tests natively on Windows, macOS and Linux ARM64,
but locally only compilation for Windows is checked (`lint:go-compile-windows`):
keep tests independent of path separators and line endings.

### Handler composition

- `WrapHandler` with `GroupOrAttrs` (`wrap_handler.go`, `goa.go`)
  is the building block for handlers which wrap another handler.
- `NewContextHandler` and `NewDefaultContextLogger` (`context_handler.go`) are built on it:
  the actual handler, with attrs/groups added by `ContextWith*`,
  is stored in a `context.Context`.
- Wrapping handlers also provide a `NewXxxMiddleware` constructor
  for use with `github.com/samber/slog-multi`.

## Mandatory Rules

### Contribution Requirements

- Write code comments and documentation in English.
- Documentation describes the current state of the project,
  not the history of its changes or code which no longer exists.
- When a check fails, fix the cause, whether it is in the code or in the test itself.
  Suppress a linter warning only when it is a false positive,
  ignores the specifics of the current implementation,
  or its fix would make the code worse;
  suppress it narrowly (a specific rule at a specific place) and state the reason next to it.
  When the cause cannot be fixed within the task,
  report it instead of skipping the test or silencing the linter.

## Conventions

- Files named `*.*.go` (e.g. `mock.handler_test.go`) are generated:
  excluded from linters, never edit by hand.
- `CHANGELOG.md` is generated by git-cliff from Conventional Commits during release.

## Common Gotchas

### Constructor Configuration

New constructors with configuration should take a `XxxConfig` struct by value
and follow the Resolvable Config Struct convention (skill go-engineering-policy).

Existing APIs use other styles for historical reasons and are kept for compatibility:

- `LayoutHandlerOptions` is passed by pointer on purpose:
  it mirrors `slog.HandlerOptions` so `LayoutHandler` can replace `slog.TextHandler`.
  Do not copy this style for handlers without such a stdlib counterpart.
- Functional options (`ErrorAttrsOption`, `ContextHandlerOption`) are legacy.
